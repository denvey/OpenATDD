# 验收卡：optimize-atdd-runtime-cost

## 目标

在保留验收优先、技术方案检查点、AI 自验收和人工 UAT 的前提下，减少精简 ATDD 与完整 OpenATDD 的模型上下文、命令往返、耗时和 Token，并用可重复评测证明优化没有削弱交付质量。

## 建议用户旅程

1. 使用者只描述要什么功能以及如何使用，不需要掌握 OpenATDD 的内部命令。
2. AI 只加载当前复杂度与风险需要的规则，先形成简短、可观察的验收结果和技术方案检查点。
3. Quick 自动继续；Standard / Deep 在既有两次确认后，由 AI 完成实现，不增加新的流程确认。
4. AI 运行相关检查和真实用户旅程，失败则修复并重新验证；程序生成证据与 UAT 交接。
5. 人按照 UAT 步骤验收功能；维护者从报告比较优化前后的质量、命令往返、耗时和 Token。

## 验收标准

### AC-01 [AUTO] [BLOCKING] 优化后仍保留完整的人机职责链
- 前提：用户只给出一句功能目标和使用方式。
- 操作：分别执行 Quick、Standard 和 Deep 的优化工作流。
- 结果：三条路径都保持“AI 推导验收 → 技术方案检查点 → AI 实现 → AI 自验收 → 人工 UAT”；Quick 不增加例行暂停，Standard / Deep 仍只有验收与方案两次人工确认。
- 证据：profile 快照、工作流回归测试和生成的 UAT 交接。

### AC-02 [AUTO] [BLOCKING] 模型只接收当前阶段需要的有界规则
- 前提：现有 thin profile 为 1,285 字节，完整 Skill 为 26,858 字节且在 delivery 运行中整份注入。
- 操作：构建优化后的 thin 与 full delivery 提示，并检查安装后的 Skill 入口。
- 结果：thin v2 不超过 1,024 字节；full delivery 的常驻运行契约不超过 4,096 字节且不内嵌完整 Skill；主 Skill 只保留关键规则和阶段路由，详细规则按需读取；bare 提示保持无 OpenATDD 线索。
- 证据：字节数、SHA-256、提示快照和禁止整份注入回归测试。

### AC-03 [AUTO] [BLOCKING] 常见任务不再执行无关流程与重复验证
- 前提：旧 full 简单场景会搜索 CLI/文档、拆分 validate/dry-run/finalize 并读取生成报告；thin 会额外加载无关开发 Skill。
- 操作：在已配置的本地项目中执行优化 profile。
- 结果：thin/full 都禁止无关 Skill、外部调研和重复项目发现；Quick full 使用合并合同推进与 `finalize --fast`，不拆分成功路径、不重复读取生成状态；只有被实际风险或失败触发的阶段才加载额外规则。
- 证据：运行契约、命令轨迹 fixture 和真实报告中的归一化命令计数。

### AC-04 [AUTO] [BLOCKING] 成本报告准确区分真实命令和重复事件
- 前提：Codex JSONL 会为同一命令发送开始与完成事件，旧报告把二者都计入命令数组。
- 操作：采集 delivery JSONL、Token 和耗时并生成优化对照报告。
- 结果：同一命令执行只记录一次最终状态；每次运行继续记录总输入、缓存输入、非缓存输入、输出 Token、耗时、profile 字节数、功能结果和交接指标，并可机械比较优化前后差异。
- 证据：成对事件 fixture、报告 schema 回归和优化汇总。

### AC-05 [AUTO] [BLOCKING] 精简上下文不削弱交付质量
- 前提：简单、中等、复杂三个隐藏验收场景及旧基线报告保持冻结。
- 操作：用优化后的 thin/full profile 运行相同场景并在 Agent 退出后执行隐藏检查。
- 结果：优化组功能通过率、自验收率、技术方案率和 UAT 交接率均为 100%，错误就绪率为 0；项目现有 134 项检查继续通过。
- 证据：隐藏检查、真实模型报告、profile 工件和 `npm run check`。

### AC-06 [AUTO] [BLOCKING] 真实模型评测证明成本按预期下降
- 前提：旧报告保存相同模型、推理强度、provider 配置和每组两次运行的成本。
- 操作：在配置不降级的前提下，对三个难度运行优化后的 profile 并与旧报告聚合比较。
- 结果：thin 聚合总输入 Token 至少降低 15%、平均耗时至少降低 10%；full 聚合总输入 Token 至少降低 80%、平均耗时至少降低 50%，并将总输入控制在同轮裸 Agent 的 2 倍以内；同时报告缓存与非缓存输入、输出 Token、命令数及小样本限制，不声称统计因果。
- 证据：优化前后报告摘要、合同哈希和机械阈值验证器。

### AC-07 [AUTO] [BLOCKING] Web 预验收优先使用零模型或低模型执行
- 前提：浏览器页面快照、逐步推理和重复截图会扩大上下文；降低模型等级只能降低价格，不能自动减少输入 Token。
- 操作：为稳定 Web 旅程、动态 Web 旅程和主观视觉验收分别路由执行方式。
- 结果：稳定旅程优先运行确定性 Playwright/项目脚本，不再调用模型；动态旅程由主模型生成有界批次和断言，再交给低模型浏览器执行器在一个复用会话中操作，只返回结构化结果并仅在检查点或失败时截图；主模型只在失败诊断时接管；主观视觉结论仍由人验收。
- 证据：浏览器执行 profile、路由回归、批次/截图预算和 UAT 报告。

### AC-08 [AUTO] [BLOCKING] 优化保持兼容与 provider 安全
- 前提：项目已有 planning v1、delivery v2、mock/command/Codex adapter、用户自定义 provider 和正式 finalization。
- 操作：运行旧 schema 回归、CLI 进程测试、provider 配置测试与凭据扫描。
- 结果：现有场景和 CLI 继续可用；所有对照共享同一 provider 与配置模式；优化不输出凭据、不访问生产系统，也不自动发送通知。
- 证据：完整项目检查、报告元数据、finalization 与凭据扫描。

## 边界

- 不通过降低模型、推理强度、重复次数或隐藏验收要求制造成本下降。
- 不删除技术方案检查点、AI 自验收、人工 UAT 或 Standard / Deep 的两次确认。
- 允许把确定性的路由、状态、证据映射和报告生成移出模型上下文，由 CLI 执行。
- 正式真实模型评测在确定性回归通过后才运行；旧报告保持不变，优化报告写入新文件。
- 不测试生产部署、外部付费数据、真实账号、CAPTCHA 或人工中途回复。
