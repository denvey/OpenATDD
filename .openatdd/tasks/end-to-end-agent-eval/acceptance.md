# 验收卡：end-to-end-agent-eval

## 目标

重新设计并运行简单、中等、复杂三类端到端 Agent 评测，对比裸 Agent、精简 ATDD 核心和完整 OpenATDD，衡量真实实现、AI 预验收质量、人工验收准备度、耗时与 token。

## 建议用户旅程

1. 维护者选择简单、中等或复杂的版本化种子项目与一句用户需求。
2. 评测在隔离工作区中，用相同模型、推理强度、用户配置和重复次数运行裸 Agent、精简 ATDD 核心和完整 OpenATDD。
3. 每个 Agent 自主读取项目、形成技术方案、修改代码并执行自己认为必要的预验收；评测器不向任一组泄露路由标签、期望实现或隐藏检查。
4. Agent 结束后，评测器独立执行隐藏功能检查，并区分“真实通过”与“Agent 宣称已就绪但验收失败”。
5. 维护者查看三个难度的对照报告，比较交付质量、预验收、技术方案与 UAT 交接可用性、耗时和 Token。

## 验收标准

### AC-01 [AUTO] [BLOCKING] 三种难度都执行公平的三组端到端对照
- 前提：存在简单、中等和复杂三个版本化场景，每个场景包含可独立复制的小型种子项目和面向用户的一句需求。
- 操作：分别对裸 Agent、精简 ATDD 核心和完整 OpenATDD 运行同一场景。
- 结果：三组使用相同模型、推理强度、用户配置、超时和重复次数，工作区彼此隔离；报告明确记录三种 profile 及场景难度。
- 证据：场景定义、profile 指纹、评测报告和隔离工作区回归测试。

### AC-02 [AUTO] [BLOCKING] 评测真实实现与预验收而非只输出计划
- 前提：三个种子项目都包含可观察的用户结果和仅评测器可见的功能检查。
- 操作：Agent 在可写工作区中读取、修改并验证代码，然后结束交付。
- 结果：Agent 可以正常使用工具和项目命令；隐藏检查只在 Agent 结束后运行，并从实际工作区判断功能是否完成。
- 证据：评测适配器回归测试、Agent 工具执行记录、修改后工作区和隐藏检查结果。

### AC-03 [AUTO] [BLOCKING] 裸基线不再收到 OpenATDD 答案线索
- 前提：评测器需要为三组提供必要的运行与结果采集协议。
- 操作：构建裸 Agent 提示与隐藏验收。
- 结果：公共提示不包含 Quick / Standard / Deep、预期技术方案、决策 ID、隐藏检查关键词或 OpenATDD 特有步骤；裸组只依靠模型默认工程能力。
- 证据：生成提示快照、禁止线索回归测试和场景隐藏检查。

### AC-04 [AUTO] [BLOCKING] 精简 ATDD 核心是有界的可识别 profile
- 前提：需要测量验收优先核心能力，而不是再注入完整 529 行 Skill。
- 操作：运行精简 ATDD 组。
- 结果：精简 profile 只要求 AI 从用户需求推导验收结果、保留技术方案检查点、实现、执行预验收并准备人工 UAT；内容独立版本化且报告保存字节数与摘要指纹。
- 证据：精简 profile 文件、长度与摘要回归测试、评测报告。

### AC-05 [AUTO] [BLOCKING] 报告区分真实成功、自验收和错误就绪声明
- 前提：Agent 可能运行检查、不运行检查，或在最终功能仍错误时宣称已完成。
- 操作：评测器采集 Agent 工具记录、最终交付和独立隐藏检查。
- 结果：每次运行至少记录功能通过、是否执行自验收、宣称就绪状态、错误就绪声明和交接可用性；不把模型自述当作功能通过证据。
- 证据：报告字段、通过/失败 fixture、隐藏检查和错误就绪判定回归测试。

### AC-06 [AUTO] [BLOCKING] 报告完整比较质量与成本
- 前提：同一场景的三个 profile 均完成指定次数的真实模型运行。
- 操作：生成并验证对照报告。
- 结果：报告按场景和 profile 列出功能通过率、错误就绪率、自验收率、交接可用性、总耗时、输入/缓存/非缓存/输出 Token 及组间差异，并明示样本数与模型配置。
- 证据：真实模型报告、报告验证器和汇总输出。

### AC-07 [AUTO] [BLOCKING] 新评测不破坏现有可重现能力
- 前提：项目已有 planning-only 场景、mock / command / Codex 适配器、报告验证和用户 provider 配置。
- 操作：增加端到端评测模式并运行项目检查。
- 结果：现有 schema v1 场景、CLI 用法和 mock 回归继续通过；三组仍共享用户 provider 或共同使用显式隔离配置，配置模式记录在报告中。
- 证据：现有评测回归、CLI 进程测试、完整项目检查和 provider 探测证据。

## 边界

- 本次保留“技术方案”环节：精简与完整 profile 都要在实现前形成可审查的技术方案；评测运行时由 Agent 自主继续，不引入人工等待。
- 简单、中等、复杂表示种子项目与实现难度，不再使用路由标签作为质量分数。
- 本次不测试真实生产部署、外部付费服务、浏览器账号、CAPTCHA 或需要人工中途回复的交互。
- 真实模型正式对照每组默认重复 2 次；报告必须显示小样本限制，不将单次差异声称为因果。
