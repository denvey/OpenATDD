# 验收卡：strategy-visibility

## 目标

保持执行过程简洁，在任务完成后按需回溯当前采用的 OpenATDD 能力组合、借鉴来源、选择原因、实际调用、效果指标和可优化项，并支持完整、裸 Agent 和能力消融对照评测。

## 建议用户旅程

1. 开发者像现在一样提交需求并完成验收、方案确认和执行。
2. 任务完成后，开发者按需生成策略回溯报告。
3. 报告说明本次选择、实际调用和未调用的能力及其借鉴来源。
4. 报告结合验收、Agent、恢复、Token 和耗时数据给出可验证的效果。
5. 开发者查看完整、裸 Agent 与能力消融的差异和下次优化建议。

## 验收标准

### AC-01 [AUTO] [BLOCKING] 正常执行保持零额外干扰
- 前提：已初始化的 OpenATDD 项目正在交付任务。
- 操作：任务完成路由、实现、验证和 finalization。
- 结果：运行过程中不增加策略播报、问题、Token 上下文或确认步骤；未请求回溯时，现有 1.0 体验保持不变。
- 证据：兼容性、交互轮次和默认 CLI 输出回归测试。

### AC-02 [ASSISTED] [BLOCKING] 完成后按需生成可理解的策略回溯
- 前提：任务已有路由、执行或验收状态。
- 操作：开发者请求回溯本次采用的方案。
- 结果：用当前对话语言生成一份简短报告，说明任务深度、选择理由、能力借鉴来源、策略选择、实际调用、未调用项及原因，并明确不展示内部思维链。
- 证据：Quick、Standard、Deep 回溯快照，真实 CLI 输出和人工可读性判断。

### AC-03 [AUTO] [BLOCKING] 实际调用、效果和证据可追溯
- 前提：任务产生 Agent、调研、审查、恢复、finalization 或评测记录。
- 操作：开发者生成策略回溯或机器可读输出。
- 结果：报告只从确定性状态和证据派生，展示实际 Agent/审查/恢复记录及可用的人类轮次、首次验收、Token、缓存 Token、耗时和通过率；每项结论可链接到来源，缺失指标明确标为不可用。
- 证据：状态派生、指标聚合、缓存 Token 和缺失值回归测试。

### AC-04 [ASSISTED] [BLOCKING] 对照评测能说明效果并给出优化建议
- 前提：存在完整 OpenATDD、裸 Agent 和一个或多个能力消融配置。
- 操作：同一版本化场景重复运行并生成对照报告。
- 结果：报告列出每组启用能力、通过率、人类交互、过度设计、合同违规、Token/时间及相对差异，并依据证据提出“保留、减少、关闭或继续观察”的建议；不因单个场景得分相同就宣称框架更优。
- 证据：版本化消融配置、隐藏检查、对照报告和人工结论判断。

## 边界

- “借鉴来源”是能力设计的来源说明，不表示运行或依赖外部框架。
- 不集成 OpenSpec，不增加第三次确认，不展示隐藏思维链或敏感上下文。
- 1.0 已有默认体验保持不变；回溯和消融评测是任务完成后的可选诊断能力。
- 不在运行过程中实时播报策略，也不新增持久开关或配置负担。
- 本次不开发 Dashboard，也不把一次小样本对照包装成普遍优越性结论。
